# Authors & Identity

An **author id** records who created or updated a document (`createdBy` / `updatedBy`). It's just a string, owned by your domain — but two ids are reserved by Pact.

## The two reserved authors

| Author id | Meaning |
|-----------|---------|
| `_system` | Seed / system-generated content. Written via `createAsSystem`. By default treated as a seed doc and **excluded from sync** (every client reseeds the same content locally). |
| `_local` | Placeholder for writes made *before* the client has claimed a real identity on a server. **The server rejects any push containing a `_local` author.** |

The `_local` author is the safety mechanism that lets a brand-new, never-connected client be fully usable offline: it can create and edit freely, and nothing leaks to a server under an ambiguous identity. The price is that those documents can't sync until you claim a real id and rewrite them.

## Identity flow

```ts
await store.setAuthor('us-alice'); // records current author in _config/author
await store.reassignLocalAuthor('us-alice'); // rewrites _local docs to a real id so they can sync
```

- `setAuthor` records the current author in `_config/author`. From now on, new writes are stamped `us-alice`. This is persisted, so the identity survives restarts (restored by `Store.create`).
- `reassignLocalAuthor` walks existing documents authored by `_local` and rewrites them to the real id. **Call it once, right after the first `setAuthor`**, so the offline backlog becomes syncable.

::: warning Pushing `_local` is an error
If you skip `reassignLocalAuthor`, any pre-identity documents will be rejected by the server on push. The fix is always: claim an identity, then reassign.
:::

## Authors as documents

Some domains model authors *as documents* — e.g. a `users/` collection with a row per person. The `onSetAuthor` domain hook lets you materialize that entity the first time an identity is set:

```ts
const domain: StoreDomain = {
  onSetAuthor: async (store, authorId) => {
    const users = store.collection('users');
    if (!(await users.get(authorId))) {
      await users.create(authorId, { displayName: authorId });
    }
  },
};
```

Now `setAuthor('us-alice')` both records the identity *and* ensures a `users/us-alice` document exists to hang a display name, avatar, etc. off of.

## System content

Reference data and anything generated by the deployment itself is written under `_system`:

```ts
await store.createAsSystem('units', 'unit-gram', { label: 'gram', symbol: 'g' });
```

Because `_system` docs are seeds by default, they don't sync — every client materializes the same catalog locally. The moment a real author edits one, it stops matching the seed rule and starts syncing normally. See [Seeds](/guide/seeds) for the full story.
